03 / HANDOFF

학습 전에 코드가 만드는 시작 상태를 검증합니다.

Policy가 잘 배우려면 실제 배포와 같은 코드 정렬을 거친 상태에서 시작해야 합니다. 이 단계에서는 모델 성능보다 센서·정렬·controller 연결을 먼저 확인합니다.

센서 추정목표 위치 · 로봇 상태
코드 정렬base + torso + 선택 팔
READY 검사거리 · 속도 · 관측 품질
상태 저장물리·controller·관측 이력
12cm추정 목표 위치 위의 TCP 시작 목표

Pick은 물체, place_on은 지지면을 기준으로 합니다. 손가락 끝과 물체 표면의 실제 간격을 직접 맞추는 값은 아닙니다.

5cm시작 목표 주변의 거리 허용 범위

감속·관측 조건까지 5프레임 연속 만족하면 제어를 넘깁니다. 모델은 남은 관측 오차를 보정합니다.

python -m bench.sim.learning.run collect-handoffs \
  --task cook_broccolini --output outputs/local_skills/pilot

영상과 결과에서 확인할 것

  • 목표 물체와 손의 추정 위치가 같은 좌표계인지, TCP/FK가 일치하는지 확인합니다.
  • 베이스·몸통·팔이 충돌 없이 준비 위치에 도달하고 감속하는지 확인합니다.
  • Place 후보에서 물체가 실제로 잡혀 있는지 확인합니다. 원본 assisted-grasp 제약을 풀면서 떨어진 후보는 거절될 수 있습니다.
  • data/handoffs/index.json의 accepted/rejected 기록을 봅니다. 모든 후보를 억지로 통과시키지 않습니다.
12cm와 5cm는 아직 물리 rollout으로 검증하지 않은 초기값입니다.

거리·속도·관측 조건을 바꾸면 새 runtime 규격으로 handoff를 다시 수집합니다. 기존 bank와 checkpoint는 runtime hash로 연결돼 있으므로 새 --output 실험 경로를 사용합니다.

다음 단계로 넘어갈 조건

Pick의 train/validation 시작 상태를 안정적으로 만들고, 준비 실패 이유를 설명할 수 있어야 합니다. 현재 guard는 근거리 TCP/depth 기반이며 완전한 전신 collision planner는 아닙니다.

04 / PICK TEACHER

Pick teacher를 학습하고 첫 rollout부터 HIL을 켭니다.

Teacher는 Gaussian SAC/RLPD 계열 정책입니다. 관절·센서 특징에 privileged 정보를 더해 학습하지만, 코드 정렬과 실행 gate는 센서 정보만 사용합니다.

Teacherprivileged 상태 → 제안 행동
사람 개입필요할 때 행동 교체
공통 실행기제한 후 실제 행동 전송
Replay → SAC실제 행동을 저장·학습

A. 검증된 BC 데이터가 있으면

원본 행동을 현재 팔 제어 규격으로 변환하고 물리 성공을 확인한 replay로 actor를 먼저 초기화합니다.

python -m bench.sim.learning.run collect-demonstrations \
  --skill pick --output outputs/local_skills/pilot
python -m bench.sim.learning.run train-teacher \
  --skill pick --output outputs/local_skills/pilot \
  --offline-replay outputs/local_skills/pilot/data/pick_offline_replay.pt \
  --steps 5000 --human-port 8766

B. 원본 BC 구간이 통과하지 못하면

BC를 생략하고 랜덤 초기화에서 RL + 사람 교정으로 시작합니다. HIL은 별도 선행 알고리즘이 아니라 online RL에 붙는 개입 방식입니다.

python -m bench.sim.learning.run train-teacher \
  --skill pick --output outputs/local_skills/pilot \
  --steps 5000 --human-port 8766
사람 개입 화면: http://127.0.0.1:8766

학습 프로세스와 같은 PC에서 엽니다. 카메라를 보고 선택 팔 7개 관절과 그리퍼를 조절하며, 버튼 또는 Space를 누르는 동안 개입합니다. Remote 서버라면 SSH port forwarding으로 로컬에 연결합니다. 팔 policy는 base·torso·반대 팔을 고정합니다.

5000 step은 연결·학습 업데이트를 확인하는 짧은 실험 예시입니다. 수렴이나 성공률을 보장하는 학습량이 아닙니다.

사람 없이 validation을 평가합니다.

python -m bench.sim.learning.run evaluate \
  --skill pick --task cook_broccolini --split validation \
  --episodes 20 --output outputs/local_skills/pilot
# 이어서 학습하려면 기존 checkpoint를 재개합니다.
python -m bench.sim.learning.run train-teacher \
  --skill pick --output outputs/local_skills/pilot \
  --resume --steps 5000 --human-port 8766
다음 단계로 넘어갈 조건

사람 도움 없이 잡기·들기·후퇴를 완료하고, 최종 상태에서 실제로 물체를 유지해야 합니다. Reward 증가만 보지 말고 무개입 성공률·개입 횟수·센서 오판을 함께 확인합니다. Pilot validation 한 instance는 연결 확인용이며 일반화 검증으로는 부족합니다.

05 / PLACE TEACHER

학습한 pick으로 잡은 뒤 place teacher를 시작합니다.

Place는 물체가 손에 있어야 시작할 수 있습니다. 그래서 먼저 pick을 확인하고, 실제로 잡힌 상태를 place의 reset 데이터로 연결합니다.

Pick teacher 실행잡기 · 들기 · 후퇴
Place 코드 정렬지지면 근처 준비
Place handoff 저장실제 파지 + 센서 이력
Place teacher + HIL내리기 · 해제 · 안정화
python -m bench.sim.learning.run collect-handoffs \
  --task cook_broccolini --output outputs/local_skills/pilot \
  --pick-checkpoint outputs/local_skills/pilot/runs/pick/teacher.pt
python -m bench.sim.learning.run train-teacher \
  --skill place_on --output outputs/local_skills/pilot \
  --steps 5000 --human-port 8766
python -m bench.sim.learning.run evaluate \
  --skill place_on --task cook_broccolini --split validation \
  --episodes 20 --output outputs/local_skills/pilot \
  --pick-checkpoint outputs/local_skills/pilot/runs/pick/teacher.pt

첫 place 학습 예시에서는 BC를 생략했습니다. 새 시작 상태에서도 원본 데모가 성공하는 경우에만 pick과 같은 방식으로 검증한 offline replay를 사용합니다.

다음 단계로 넘어갈 조건

물체가 올바른 지지면에 놓이고, 그리퍼를 연 뒤 손이 후퇴해도 놓인 상태가 유지돼야 합니다. Pick 실패와 place 준비 실패도 전체 평가의 분모에 포함합니다.

기본 설정은 태스크당 train 160 / validation 20 / test 20 instance입니다. 데이터·물리 rollout 비용이 크면 --instances로 작은 집합부터 늘립니다. Handoff 수집에서 --task를 빼면 다섯 태스크를 대상으로 처리합니다.

Full 실험도 같은 순서입니다.

Pick teacher 학습 → 무개입 validation → --pick-checkpoint로 place handoff 수집 → place teacher 학습 → 무개입 validation. 앞 단계 명령의 --output과 checkpoint 경로를 outputs/local_skills/full 기준으로 맞춥니다. 새 output에서는 teacher가 새로 초기화되며 pilot 가중치가 자동으로 이어지지는 않습니다.

평가는 태스크별로도 봅니다.

전체 평균만 높고 특정 물체나 지지면에서 반복 실패할 수 있습니다. 각 태스크의 준비 성공률, 무개입 조작 성공률과 거절 원인을 비교하고 시작 상태 분포를 보완합니다.

다음 단계로 넘어갈 조건

두 teacher가 여러 원본 instance와 코드 handoff 상태에서 검증돼야 합니다. Student가 모방할 만큼 신뢰할 수 있는 성공 rollout을 확보합니다. 마지막 test split은 반복 튜닝에 사용하지 않습니다.

07 / STUDENT

Teacher 행동을 영상 student로 옮기고 DAgger로 보완합니다.

Student는 RGB·로봇 상태·목표·짧은 관측 이력으로 행동합니다. Teacher의 정확한 물체 위치는 student 입력으로 전달하지 않습니다.

Teacher rollout정답 상태로 행동 생성
학습 쌍센서 관측 ↔ teacher 행동
Visual BCCNN + GRU student
DAgger 반복학생 방문 상태에서 teacher 질의

검증된 full teacher로 두 student를 학습합니다.

for learning_skill in pick place_on; do
  python -m bench.sim.learning.run collect-distillation \
    --skill "$learning_skill" --split train --episodes 50 \
    --output outputs/local_skills/full
  python -m bench.sim.learning.run collect-distillation \
    --skill "$learning_skill" --split validation --episodes 20 \
    --output outputs/local_skills/full
  python -m bench.sim.learning.run train-student \
    --skill "$learning_skill" --output outputs/local_skills/full
  python -m bench.sim.learning.run dagger \
    --skill "$learning_skill" --split train --episodes 50 \
    --output outputs/local_skills/full
  python -m bench.sim.learning.run train-student \
    --skill "$learning_skill" --output outputs/local_skills/full
done

50 / 20 episodes는 첫 수집 배치의 예시이며 충분한 데이터량을 의미하지 않습니다. 태스크·물체·시작 오차별 성공 궤적을 확인하면서 늘립니다. Train과 validation은 원본 episode 단위로 분리합니다.

DAgger에서 무엇이 달라지나요?

Teacher가 만든 상태만 모방하면 student가 조금 틀렸을 때의 관측이 부족합니다. DAgger에서는 student를 직접 움직이고, student가 방문한 상태의 정답을 teacher에게만 주어 추가 행동 label을 얻습니다.

다음 단계로 넘어갈 조건

outputs/local_skills/full/deploy/v1/에 manifest.json, pick.pt, place_on.pt가 생성되고, validation에서 실제 student rollout을 평가할 수 있어야 합니다. 모방 loss 감소만으로 조작 성공을 판단하지 않습니다.

08 / EVALUATION & DEPLOYMENT

Student를 무개입으로 평가한 뒤 실로봇 연결을 진행합니다.

마지막 평가도 처음과 같은 센서 기반 코드 정렬을 사용합니다. Teacher의 정확한 위치나 사람 교정 없이 두 student가 동작하는지 확인합니다.

python -m bench.sim.learning.run evaluate \
  --skill pick --split test --episodes 50 \
  --output outputs/local_skills/full \
  --bundle outputs/local_skills/full/deploy/v1
python -m bench.sim.learning.run evaluate \
  --skill place_on --split test --episodes 50 \
  --output outputs/local_skills/full \
  --bundle outputs/local_skills/full/deploy/v1

Bundle에 두 모델이 있으면 place 평가는 student pick부터 실행합니다. Teacher pick으로 파지를 대신해 주는 평가와 구분할 수 있습니다.

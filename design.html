이 파일이 하는 일

    왼쪽 경로는 앞으로 만들 구조입니다. 기존 robot adapter·planner·demo reader를 재사용하며, pick/place_on 파일을 각각 복제하지 않습니다.

    기존 파일에서 바꿀 부분

    skills/pick_up_from.py · place_on.py
    기존 외부 호출을 새 실행기로 연결합니다.

    skills/robot/config/ · adapters/ · 관련 운동학
    RB-Y1의 joint·camera·controller 가정을 R1Pro에 맞게 적용·검증합니다.

    bench/sim/sim_boot.py
    R1Pro 로딩과 관측·controller 규격을 검사합니다.

    skills/tests/test_boundaries.py
    policy.py의 지연 Torch 로딩만 허용하고, 실행 코드의 simulator·oracle 접근 금지는 유지합니다.

    생성되는 데이터와 배포 파일
    outputs/local_skills/
├── data/
│   ├── demo_index/       원본 구간·split
│   ├── handoffs/         코드 접근 결과
│   └── distillation/     관측 ↔ teacher 행동
├── runs/<실험>/
│   ├── config.yaml       확정된 실험 설정
│   ├── checkpoints/      학습 모델
│   ├── replay/           학습 재시작 데이터
│   └── evaluation/       성공·오판·개입 기록
└── deploy/<버전>/
    ├── manifest.json     규격·정규화·시작/종료 조건
    ├── pick.pt           Pick student
    └── place_on.pt       Place_on student

    이들은 생성되는 산출물입니다. 배포 bundle에는 teacher·critic·정답 상태를 넣지 않습니다. Student checkpoint와 실행 설정만 전달합니다.

    첫 구현의 제어 범위
    접근은 base·torso·팔로 준비합니다. 정밀 구간은 사용하는 팔+gripper가 움직이고 나머지는 유지합니다. Teacher와 student에 같은 제어 범위를 적용합니다.

    단계를 누르면 담당 파일과 다음 단계 조건이 나옵니다. 모든 단계 전환은 executor.py가 담당합니다.

    다음 단계 조건

    조건이 안 맞으면

    정답 상태는 학습 경로에만

    env.py가 정답 상태를 teacher.py의 actor·critic·reward·별도 evaluator에 제공합니다. 접근·gate·실행용 성공 확인에는 센서 추정만 사용합니다. 정답으로 파지·tracking 정보를 초기화하지 않습니다.

    pick_up_from.py / place_on.py가 executor.py를 호출하고, 명령은 기존 robot adapter를 통해 로봇으로 전달합니다. 배포에서는 policy.py의 student를 사용합니다. Teacher 학습에서는 같은 실행기에 학습용 teacher를 주입합니다.

    정밀 구간은 접촉 전 마지막 정렬부터 포함합니다. 원본 23차원 명령과 로컬 policy 출력의 단위·좌표·변환은 실제 R1Pro controller와 검증합니다. 실제 로봇 연결은 별도 검증이 필요합니다.

    먼저 한 물체의 pick을 끝까지 연결합니다.

    1

    R1Pro 센서·명령 규격부터 맞추기

    기존 robot adapter와 설정을 적용합니다. RB-Y1 이름만 바꾸지 않고 joint 순서, gripper 방향, FK, hold 동작을 확인합니다.

    통과 기준: 명령 의미가 맞고, 유지할 부위가 실제로 유지됨.
    2

    모델 없이 접근 → handoff 수집

    센서 추정으로 전신 자세를 준비합니다. 실제 코드 종료 상태와 센서 이력·controller 상태를 저장하고 시작 실패도 기록합니다.

    통과 기준: 정답 위치 없이 접근·gate가 동작하고 시작 분포를 측정할 수 있음.
    3

    오차가 있는 handoff에서 teacher 학습

    정답 정보를 teacher에 주고 마지막 정렬·잡기를 학습합니다. 짧은 자동 rollout으로 연결을 확인하고, BC 초기화와 HIL 교정을 결합합니다.

    통과 기준: reset·reward·행동 저장이 맞고, 반복 실패를 교정할 수 있음.
    4

    Student distillation → 직접 실행 → 교정

    센서 관측과 teacher 행동으로 학습합니다. Student가 방문한 상태에 teacher label을 추가하는 DAgger 반복으로 실행 중 생기는 오차를 보완합니다.

    통과 기준: student 입력에 정답 상태가 없고, 전체 실행을 무개입으로 평가할 수 있음.
    5

    Place_on 연결 → 같은 코드로 5태스크 확장

    Pick 결과의 센서 기반 파지 추정을 place_on에 이어 전달합니다. Skill·goal·checkpoint를 바꾸고 파일은 복제하지 않습니다.

    통과 기준: 준비·정밀 조작·종료 판단·마무리까지 정답 입력 없이 연결됨.
    전체 성공률

    접근·재관측 실패도 분모에 넣습니다. 사람 도움을 받은 완료와 무개입 성공을 구분합니다.

    판단의 오판

    센서 기반 gate·성공 판단을 정답 evaluator와 비교합니다. 정답은 행동 결정에 전달하지 않습니다.

    원본 데이터 재사용

    Label·snapshot·reader는 재사용합니다. 새 접근 코드와 student가 만드는 상태는 추가 rollout으로 확보합니다.

    파일별 전체 설명과 학습 흐름

    skills/learned/contracts.py

    파일 사이에서 전달할 데이터의 의미를 고정합니다.

    입력·출력의 이름, 좌표계, 제어 범위를 한 곳에서 정의합니다. 기존 로봇 공통 규격은 재사용합니다.

    입력: Skill 종류, 관측·action의 의미, 좌표계, 시작·종료 조건
    출력: SkillSpec · SkillObservation · PolicyAction · StepRecord

    • 기존 ObservationPacket·RobotCommand·SkillResult를 재사용합니다.
    • 새로운 skill 관측과 로컬 action의 타입·의미를 정의합니다.
    • Teacher/student가 같은 action 계약을 지키도록 합니다.

    책임 경계: 정답 물체 상태는 이 파일에 넣지 않습니다. 학습용 privileged 상태는 env.py에 둡니다.

    skills/learned/observe.py

    센서 관측과 추정을 실행기·student의 입력으로 만듭니다.

    기존 observation adapter와 perception을 호출합니다. 새 인식 알고리즘을 한 파일에 모두 구현하지 않습니다.

    입력: 카메라 영상 · proprio · tracking 결과 · 사용 가능한 goal
    출력: 로봇 상태 · 추정 목표/관측 품질 · 이력 · student 입력

    • 영상과 proprio의 시점, 로봇 상태와 관측 이력을 정리합니다.
    • 물체·지지면 추정과 가시성·tracking 상태를 전달합니다.
    • 영상·gripper·이력으로 파지/놓기 상태를 추정합니다.

    책임 경계: 여기는 상태 추정만 합니다. 다음 단계로 넘어갈지는 executor.py가 결정합니다. 정답 pose는 읽지 않습니다.

    skills/learned/code_motion.py

    접근·전신 자세 준비·마무리 이동을 담당합니다.

    기존 planner·IK·명령 기능을 재사용합니다. Pick/Place_on은 설정에 따라 시작 후보와 마무리 목표를 바꿉니다.

    입력: 센서 기반 관측 · SkillSpec · 현재 단계
    출력: 접근/유지/후퇴 명령 · READY/REOBSERVE/REPLAN/FAILED

    • Base·torso·팔을 준비하고 마지막 정렬 공간을 남깁니다.
    • 자세·속도·관측 품질·도달 가능성으로 시작 준비를 검사합니다.
    • 파지/놓기 확인 후 현재 상태에서 마무리 이동을 만듭니다.

    책임 경계: 정밀 policy 행동은 만들지 않습니다. 기존 pick 전체를 접근 코드로 호출하지 않고 필요한 planner·이동 기능을 재사용합니다.

    skills/learned/policy.py

    Student 모델을 정의하고 관측에서 행동을 생성합니다.

    배포 모델 로딩, 정규화, 추론, 모델 내부 상태 관리가 한 곳에 모입니다. ACT·DP·flow 비교도 이 경계를 유지합니다.

    입력: 영상 · proprio · goal · 이력 + student checkpoint/manifest
    출력: 사용하는 팔 + gripper의 PolicyAction

    • Student 모델을 정의하고 배포 checkpoint를 읽습니다.
    • 같은 정규화·action 규격으로 정밀 행동을 계산합니다.
    • Skill 전환 시 모델 내부 상태를 정리합니다.

    책임 경계: 접근 계획·reward·RL 업데이트는 하지 않습니다. Teacher actor와 critic은 teacher.py에 둡니다. Torch는 모델 로딩 시 지연 import합니다.

    skills/learned/executor.py

    현재 단계와 제어권을 결정하는 공통 실행기입니다.

    실행 상태 머신은 이 파일 하나에 둡니다. Teacher/student의 행동 생성기를 교체해도 코드 접근과 센서 판단은 유지합니다.

    입력: Skill 요청 · 관측 · SkillSpec · 행동 생성기
    출력: 단계 전환 · 공통 robot adapter로 보낼 명령 · SkillResult

    • 관측 → 준비 → 시작 검사 → 정밀 policy → 성공 확인 → 마무리를 연결합니다.
    • Timeout·재관측·재계획·실패 반환을 관리합니다.
    • Policy 명령과 나머지 부위의 hold 명령을 같은 제어 경로로 전달합니다.

    책임 경계: 인식·이동 계획·모델 학습을 중복 구현하지 않습니다. 성공 추정은 observe.py가, 단계 전환은 이 파일이 맡습니다.

    bench/sim/learning/env.py

    공통 실행기와 simulator를 연결합니다.

    Reset·reward·학습용 정답 상태·정답 평가를 제공하는 유일한 신규 환경 연결부입니다.

    입력: Simulator · 실험 설정 · handoff snapshot · policy 행동
    출력: Student 관측 · teacher용 privileged 상태 · reward · 평가 결과

    • 센서 기반 접근을 실행하거나 실제 handoff를 복원해 reset합니다.
    • Snapshot과 controller·tracking·필요한 관측 이력을 복원하거나 다시 구성합니다.
    • 학습용 정답 terminal과 실행용 센서 성공 판단을 별도로 다룹니다.

    책임 경계: 정답 pose로 접근 코드나 파지/tracking 기억을 초기화하지 않습니다. 정답 정보는 teacher·critic·reward·별도 평가에만 전달합니다.

    bench/sim/learning/data.py

    원본·handoff·replay·학습 기록의 읽기와 저장을 담당합니다.

    기존 bench/demo reader를 사용합니다. 데이터 종류별로 파일을 계속 늘리지 않고 이 파일 안에서 reader/writer를 구분합니다.

    입력: 원본 label·영상·raw 데이터 · 코드 종료 상태 · 실행 전이
    출력: 데모 index · handoff bank · RL replay · distillation dataset

    • Skill 후보 구간과 train/validation을 정리하고 영상·행동 시점을 확인합니다.
    • Snapshot·센서 이력·실제 전송 행동·사람 교정을 기록합니다.
    • Student dataset에서는 허용된 관측과 teacher 행동만 반환합니다.

    책임 경계: 원본 데이터는 변경하지 않습니다. 원본 23차원 action을 단순히 잘라 쓰지 않고 controller 의미와 새 제어 범위를 검증합니다.

    bench/sim/learning/teacher.py

    정답 상태로 정밀 조작을 배우는 teacher를 학습합니다.

    Gaussian state actor·Q critic, 선택적 BC 초기화, SAC/RLPD 계열 업데이트와 HIL 교정을 묶습니다.

    입력: env.py의 privileged 상태 · 원본/online replay · 사람 교정
    출력: Pick/Place_on teacher checkpoint · 실행 행동 · 학습 기록

    • 실제 추정 기반 코드 handoff에서 teacher를 학습합니다.
    • Actor/critic 업데이트와 teacher checkpoint를 관리합니다.
    • Human override를 같은 action 규격에 적용하고 실제 전송 행동을 저장합니다.

    책임 경계: 사람이 base·torso까지 움직이는 복구는 팔 policy의 일반 행동 교정과 구분합니다. 복구 후 시작 조건을 다시 검사합니다.

    bench/sim/learning/student.py

    Teacher 행동을 센서 관측으로 재현하도록 student를 학습합니다.

    Teacher rollout 수집 → BC/distillation → student rollout → teacher 교정 → 재학습을 담당합니다.

    입력: 센서 관측 ↔ teacher 행동 dataset · teacher checkpoint · 학습 환경
    출력: Student checkpoint · 추가 교정 데이터 · 배포 bundle

    • policy.py의 같은 Student 모델을 학습합니다.
    • Student가 방문한 상태에 teacher 행동을 추가하는 DAgger 반복을 수행합니다.
    • 모델과 관측/action/정규화/시작·종료 규격을 함께 export합니다.

    책임 경계: Student에는 정답 상태를 넣지 않습니다. 보이지 않는 정보를 distillation만으로 복원할 수는 없어 재관측·이력을 함께 설계합니다.

    bench/sim/learning/run.py

    설정을 읽고 데이터 준비·학습·평가 작업을 시작합니다.

    실험마다 별도 script를 만들지 않습니다. 하나의 진입점에서 작업 모드를 선택하고 파일들을 연결합니다.

    입력: 작업 모드 · config.yaml · 대상 skill · 모델/데이터 경로
    출력: 실험 실행 · 확정 설정 · 결과 집계

    • 데이터 준비·handoff 수집·teacher 학습·student 학습·교정·평가를 선택합니다.
    • Simulator와 모델의 시작 순서를 관리합니다.
    • 준비 성공률·정밀 성공률·전체 성공률·판단 오판을 집계합니다.

    책임 경계: RL 수식이나 정답 성공 predicate는 여기에 중복하지 않습니다. 학습은 teacher/student, 환경 판정은 env.py가 담당합니다.

    bench/sim/learning/config.yaml

    코드에 흩어질 실험 선택과 수치 기준을 모읍니다.

    공통 값은 공유하고 pick/place_on의 시작·종료 조건만 따로 둡니다. 수치 기준은 rollout으로 검증해 정합니다.

    입력: 태스크·로봇·센서·제어 범위·학습/평가 실험 선택
    출력: 하나의 확정 실험 설정 · 배포용 실행 설정 일부

    • tasks / robot / observation / handoff를 정의합니다.
    • teacher / student / evaluation 설정을 모읍니다.
    • 5태스크는 halve_an_egg, store_honey, cook_broccolini, make_rose_centerpieces, picking_up_trash로 지정합니다.

    책임 경계: 배포 코드는 bench/의 설정 파일을 직접 읽지 않습니다. 필요한 실행 설정만 manifest.json에 포함합니다. 실기에서 없는 센서를 기본 제공으로 가정하지 않습니다.

    Student 배포: 준비하고, 보면서 조작하고, 확인합니다.

    왼쪽 열에서 시작해 화살표를 따라갑니다. 가운데는 영상 기반 조작 반복, 오른쪽은 성공 확인과 마무리입니다.

    배포 경로 전체가 센서 관측을 사용합니다. Base·torso·반대 팔은 정밀 구간에서 유지하고, 학생 policy가 마지막 정렬부터 잡기/놓기를 담당합니다.

    • 다음 관측 · 상태 추정 [추정] → 성공 조건 유지?

    Skill 요청 → 실행기

    pick_up_from.py / place_on.py
    기존 skill 진입점이 target·support·사용할 팔을 전달합니다. 공통 executor를 시작하고 해당 student checkpoint를 선택합니다.

    입력: 상위 skill 요청 · 배포 manifest
    출력: SkillSpec · 공통 실행기 · 초기 상태
    다음 단계: observe.py로 센서 관측을 받습니다.

    센서 관측 · 대상 추정

    observe.py
    기존 관측 adapter와 perception을 호출합니다. 대상과 손의 관계, 로봇 상태, 관측 품질을 공통 관측으로 묶습니다.

    입력: 실기 센서 · 사용 가능한 goal
    출력: SkillObservation · student용 센서 입력
    다음 단계: code_motion.py가 추정된 목표를 기준으로 접근합니다.

    접근 · 전신 자세 준비

    code_motion.py
    팔이 정렬·파지·lift를 수행할 여유가 있는 자세를 만듭니다. 물체의 정확한 위치를 보장하는 것이 아니라 추정 목표 주변으로 접근합니다.

    입력: 추정 대상/지지면 · 로봇 상태 · SkillSpec
    출력: 접근 명령 · 준비 상태 보고
    다음 단계: 시작 조건을 검사합니다. 접근·감속 중 관측은 계속 갱신합니다.

    시작 준비됨?

    code_motion.py + executor.py
    코드 이동 파일이 자세·속도·도달 가능성·관측 품질을 검사하고 실행기가 전환합니다. 정답 pose 일치를 요구하지 않습니다.

    입력: 센서 관측 · 시작 규격
    출력: READY 또는 재관측/재계획 요청
    다음 단계: 예: policy 시작. 아니오: 관측·준비 반복. 제한 초과: 실패.

    Student 행동 계산

    policy.py
    영상·proprio·goal·이력으로 사용하는 팔과 gripper의 행동을 생성합니다. 정확한 물체 수치를 몰라도 관측 가능한 잔여 오차를 보정하도록 학습합니다.

    입력: Student 센서 입력 · checkpoint
    출력: PolicyAction
    다음 단계: executor가 같은 action 규격으로 명령을 전송합니다.

    명령 전송 · 로봇 step

    executor.py + robot adapter
    실행기가 제한·정규화·단위 변환을 적용한 뒤 공통 adapter로 명령을 보냅니다. 사용하지 않는 부위는 실제 hold controller로 유지합니다.

    입력: PolicyAction · 현재 로봇/controller 상태
    출력: 실제 전송 명령 · 갱신된 센서
    다음 단계: observe.py가 다음 관측을 정리합니다.

    다음 관측 · 상태 추정

    observe.py
    로봇이 움직인 뒤 영상·proprio·이력을 갱신합니다. 파지·놓기 상태를 센서로 추정하고 다음 policy 입력도 만듭니다.

    입력: 이동 후 센서 · tracking 이력
    출력: 새 관측 · 성공 판단용 추정
    다음 단계: executor.py가 종료 조건을 확인합니다.

    성공 조건 유지?

    executor.py
    센서 기반 파지/놓기 추정이 종료 규격과 유지 시간을 만족하는지 판단합니다. Simulator 성공 predicate는 읽지 않습니다.

    입력: observe.py의 상태 추정 · ExitSpec
    출력: 다음 정밀 행동 또는 마무리 전환
    다음 단계: 아니오: 새 관측으로 policy 반복. 관측 불량은 재관측, 제한 초과는 실패.

    마무리 이동

    code_motion.py
    현재 관측과 파지 추정으로 다음 이동을 계획합니다. Pick 후 추가 lift·이동, place_on 후 후퇴를 수행합니다.

    입력: 현재 로봇·추정 파지 상태
    출력: 마무리 명령 · 완료 상태
    다음 단계: 마무리까지 완료하면 실행기가 결과를 반환합니다.

    결과 반환

    executor.py
    실행 상태, 실패 이유, policy 버전, 최종 센서 추정을 반환합니다. 성공은 실행기의 센서 판단이며 정답 기반 성능 평가는 별도입니다.

    입력: 전체 단계의 실행 기록
    출력: SkillResult · 상위 코드가 이어 쓸 상태
    다음 단계: 다음 skill 요청을 처리합니다.

    Timeout / 복구 실패

    executor.py
    시작 준비·정밀 조작·마무리에 재시도와 시간 제한을 적용합니다. 이 상자는 모든 단계에 적용되는 공통 실패 경로입니다.

    입력: Timeout · 관측 상실 · 복구 불가
    출력: FAILED · 원인 · 실행 기록
    다음 단계: 상위 코드에 실패를 반환합니다.

    Teacher RL: 같은 준비 코드 + privileged actor + replay 업데이트

    가운데는 환경 상호작용, 오른쪽은 데이터 저장과 주기적인 learner 업데이트입니다. 점선은 데이터·가중치 전달입니다.

    Teacher는 정답 상태를 받지만 접근·gate·실행용 종료 판단은 같은 센서 기반 코드를 사용합니다. HIL 교정 뒤 실제 전송한 행동을 replay에 저장합니다. 학습용 정답 terminal과 실행기 판단은 별도입니다.

    흐름 연결

    • Teacher 실험 시작 → Reset 데이터 준비
    • Reset 데이터 준비 [Reset 후보] → 환경 reset
    • 환경 reset → 공통 접근 · READY 검사
    • 공통 접근 · READY 검사 [READY] → State actor 행동
    • 공통 접근 · READY 검사 [복구 불가] → 준비 실패도 기록
    • State actor 행동 [제안 행동] → 교정 적용 · 환경 step
    • 교정 적용 · 환경 step → Episode 종료?
    • Episode 종료? [아니오] → State actor 행동
    • Episode 종료? [예 · reset] → 환경 reset
    • Privileged 상태 제공 [정답 상태] → State actor 행동
    • Privileged 상태 제공 [Critic 상태] → Actor / critic 업데이트
    • 필요할 때 사람 교정 [HIL 교정] → 교정 적용 · 환경 step
    • 교정 적용 · 환경 step [실제 전이] → Replay에 전이 저장
    • Replay에 전이 저장 [Batch] → Actor / critic 업데이트
    • Actor / critic 업데이트 [갱신된 actor 가중치] → State actor 행동
    • Actor / critic 업데이트 [주기적 저장] → Teacher checkpoint

    Teacher 실험 시작

    run.py / config.yaml
    실험 설정을 읽고 simulator·데이터·teacher를 연결합니다. 환경과 모델의 시작 순서를 관리합니다.

    입력: 작업 모드 · 실험 설정
    출력: 학습 환경 · teacher · 기록 경로
    다음 단계: data.py에서 reset 데이터와 replay를 준비합니다.

    Reset 데이터 준비

    data.py
    원본 데모의 label·snapshot 또는 실제 코드 접근에서 만든 handoff bank를 읽습니다. 원본 데이터는 수정하지 않습니다.

    입력: 원본 reader · 데이터 index · handoff bank
    출력: Reset 후보 · 복원에 필요한 센서/controller 이력
    다음 단계: env.py가 선택한 상태로 reset합니다.

    환경 reset

    env.py
    Simulator 상태와 controller·tracking·센서 이력을 복원하거나 다시 구성합니다. 정답으로 runtime perception 기억을 채우지 않습니다.

    입력: Reset 후보 · 실험 설정
    출력: 환경 상태 · 실행용 센서 관측
    다음 단계: 공통 실행기로 접근하거나 복원한 handoff의 시작 조건을 검사합니다.

    공통 접근 · READY 검사

    executor.py / code_motion.py
    원본 장면에서는 같은 접근 코드를 실행합니다. Handoff 복원에서는 실제 저장한 문맥을 복원한 뒤 READY를 확인합니다. 준비 실패도 기록합니다.

    입력: 센서 관측 · SkillSpec
    출력: 정밀 policy를 시작할 실제 상태
    다음 단계: READY면 teacher 행동을 계산합니다. 미달이면 복구·재준비 또는 실패.

    State actor 행동

    teacher.py
    환경에서 받은 정답 상태와 로봇·goal로 행동을 계산합니다. Teacher adapter를 공통 실행기에 주입하며 실행 코드가 oracle을 읽지는 않습니다.

    입력: env.py의 privileged 상태 · robot/goal
    출력: Teacher 제안 행동
    다음 단계: 같은 명령 변환·제한을 통과해 환경에 적용합니다.

    교정 적용 · 환경 step

    env.py + executor.py
    필요하면 사람 교정을 적용하고 같은 action adapter로 전송합니다. 다음 관측과 reward, terminated/truncated를 만들고 실제 전송 행동을 기록합니다.

    입력: Teacher 행동 또는 HIL 교정
    출력: (s, a_exec, r, s') · 센서 관측 · 종료 flag
    다음 단계: Replay에 전이를 저장하며 episode 종료 여부를 확인합니다.

    Episode 종료?

    env.py
    학습용 정답 성공·실패와 timeout을 구분합니다. Terminal과 truncation은 critic bootstrap 처리에서 구분합니다.

    입력: 학습 상태 · reward · 종료 기준
    출력: 종료 flag · 마지막 transition
    다음 단계: 아니오: 다음 teacher 행동. 예: 다음 reset. 실행용 성공 판단과는 별도.

    Privileged 상태 제공

    env.py
    Simulator 정답을 teacher actor·critic·reward·별도 evaluator에만 제공합니다. 접근 코드·gate·student 입력에는 넣지 않습니다.

    입력: Simulator의 현재/다음 정답 상태
    출력: Teacher 상태 · critic 입력 · 평가 정보
    다음 단계: Actor 행동과 learner 업데이트에 사용합니다.

    필요할 때 사람 교정

    teacher.py · Human override
    정밀 구간의 잘못된 행동을 사람이 교정합니다. Base·torso 이동이 필요한 복구는 팔 action 교정과 구분하고 다시 준비합니다.

    입력: 사람 입력 · 현재 action 규격
    출력: 교정된 전송 후보 행동
    다음 단계: env/executor의 공통 제한·adapter를 거쳐 실행합니다.

    Replay에 전이 저장

    data.py
    데모와 online 전이, 사람 교정을 저장합니다. 제안 행동 대신 교정·제한 적용 후 실제 전송한 행동을 기록합니다.

    입력: 환경 step의 실제 transition
    출력: 학습 batch · 재시작 데이터
    다음 단계: 설정한 주기에 batch를 learner로 전달합니다.

    Actor / critic 업데이트

    teacher.py
    Replay batch로 Q critic과 Gaussian actor를 업데이트합니다. 선택적 BC 초기화와 HIL을 결합하고 actor 가중치를 다시 rollout에 전달합니다.

    입력: Replay batch · privileged critic 상태
    출력: 새 actor/critic 가중치 · 학습 지표
    다음 단계: 학습은 계속 반복하고 설정 주기에 checkpoint를 저장합니다.

    Teacher checkpoint

    teacher.py
    Actor·critic·정규화·설정·버전을 저장합니다. 이후 student 데이터 수집과 학습 재시작에 사용합니다.

    입력: 학습 가중치 · 실험 규격
    출력: Teacher checkpoint
    다음 단계: Student distillation 단계에서 actor를 불러옵니다.

    준비 실패도 기록

    env.py / executor.py
    Gate를 통과한 episode만 성공률의 분모로 삼지 않습니다. 전체 준비 실패와 환경·사람 비용도 별도 기록합니다.

    입력: 시작 준비 실패 · 복구 실패
    출력: 실험 기록 · 전체 평가 분모
    다음 단계: 다른 reset을 선택하거나 오류를 수정합니다.

    Student 학습: 행동 모방 → 직접 rollout → teacher 교정

    Teacher 관측을 student 입력에 복사하지 않습니다. 정답 상태는 교정 행동을 질의할 때 학습용 teacher에게만 줍니다.

    Student에는 센서 관측 o만 제공합니다. 학습용 정답 상태 s는 teacher 행동 생성·교정에만 씁니다. 같은 실행기로 student를 직접 검증하고, 보이지 않는 정보는 재관측·이력으로 보완합니다.

    흐름 연결

    • Student 실험 시작 → Teacher rollout 수집
    • Teacher rollout 수집 [o, aT] → Student 학습 데이터
    • Student 모델 생성 [모델] → BC / distillation 업데이트
    • Student 학습 데이터 [(o, aT)] → BC / distillation 업데이트
    • BC / distillation 업데이트 → Student 직접 rollout
    • Student 직접 rollout → 추가 교정 필요?
    • Student 직접 rollout [학습용 방문 상태] → 방문 상태의 정답
    • 추가 교정 필요? [예] → 방문 상태에 Teacher 질의
    • 방문 상태의 정답 [sGT] → 방문 상태에 Teacher 질의
    • 방문 상태에 Teacher 질의 [교정 label] → 교정 데이터 추가
    • 교정 데이터 추가 [다음 반복 · 추가 dataset] → BC / distillation 업데이트
    • 추가 교정 필요? [아니오 · 검증 기준 충족] → 배포 bundle export
    • 배포 bundle export [Export] → 배포에 전달할 파일

    Student 실험 시작

    run.py / config.yaml
    Teacher checkpoint와 공통 action 규격을 불러옵니다. 관측·학습·교정·평가 설정을 읽고 학습 작업을 연결합니다.

    입력: 실험 설정 · teacher checkpoint
    출력: 수집·학습·검증 환경
    다음 단계: 같은 코드 접근에서 teacher rollout을 수집합니다.

    Teacher rollout 수집

    env.py + teacher.py
    코드 접근·gate는 센서 추정을 사용합니다. Teacher만 privileged 정보를 받고 행동합니다. 원본 데모도 관측/action 규격을 검증해 연결합니다.

    입력: 공통 실행 환경 · teacher actor
    출력: 연속 센서 관측 o · teacher 행동 aT
    다음 단계: data.py가 student dataset을 만듭니다.

    Student 학습 데이터

    data.py
    영상·proprio·goal·이력과 teacher 행동을 연결합니다. 정밀 skill 경계를 넘겨 섞지 않고 정답 상태는 student loader에서 제외합니다.

    입력: Teacher rollout · 검증한 원본 구간
    출력: StudentInput · 행동 label
    다음 단계: student.py의 BC/distillation batch로 전달합니다.

    Student 모델 생성

    policy.py
    학습과 배포에서 같은 student 모델 정의를 사용합니다. 모델 로딩·추론 경계는 유지하고 ACT·DP·flow 비교도 이 파일에서 관리합니다.

    입력: 모델 설정 · action 계약
    출력: 학습 가능한 visual student 모델
    다음 단계: student.py가 teacher 행동 label로 업데이트합니다.

    BC / distillation 업데이트

    student.py
    센서 관측으로 teacher 행동을 재현하도록 student를 학습합니다. Student 입력에 privileged 상태를 넣지 않습니다.

    입력: policy.py의 모델 · (o, aT) batch
    출력: 갱신된 student 가중치
    다음 단계: Student가 직접 공통 실행기에서 rollout합니다.

    Student 직접 rollout

    student.py + env.py
    학습한 student를 실제로 움직여 관측·행동·실패를 수집합니다. 시작 코드와 gate는 그대로 쓰고 student 행동이 만든 추가 오차를 확인합니다.

    입력: Student checkpoint · 공통 실행 환경
    출력: 방문한 센서 관측 · 궤적 · 검증 결과
    다음 단계: 추가 교정이 필요한지 검증 기준으로 결정합니다.

    추가 교정 필요?

    student.py
    검증 결과와 학습 계획으로 DAgger 교정 여부를 결정합니다. 실패 지점뿐 아니라 student가 방문한 상태에 expert 행동을 질의할 수 있습니다.

    입력: Student rollout · validation 지표
    출력: 교정 반복 또는 export
    다음 단계: 예: 방문 상태에서 teacher 질의. 아니오: 검증 기준 충족 후 export.

    방문 상태의 정답

    env.py
    Student가 방문한 시뮬레이터 상태의 정답을 읽습니다. 이 값은 student나 공통 접근 코드 입력이 아니라 teacher 질의용입니다.

    입력: 시뮬레이션에서 방문한 상태
    출력: Teacher용 privileged 상태
    다음 단계: teacher.py가 해당 상태의 교정 행동을 계산합니다.

    방문 상태에 Teacher 질의

    teacher.py
    Teacher가 복구 가능한 상태인지 확인한 뒤 행동 label을 계산합니다. 모호한 관측은 재관측이 필요하며 teacher도 실패하는 상태를 무조건 label하지 않습니다.

    입력: 방문 상태의 정답 · robot/goal
    출력: 교정 행동 label · 유효성
    다음 단계: data.py에 대응하는 센서 관측과 함께 추가합니다.

    교정 데이터 추가

    data.py
    Student가 실제로 만든 상태 분포를 dataset에 추가합니다. 분석용 정답을 저장하더라도 student loader는 허용된 입력만 반환합니다.

    입력: 방문 센서 관측 · teacher 교정 행동
    출력: 증강된 student dataset
    다음 단계: 다음 BC/distillation 업데이트로 반복합니다.

    배포 bundle export

    student.py
    검증된 student와 관측/action/정규화/시작·종료 조건을 묶어 export합니다. 학습 디렉토리 설정을 배포 코드가 직접 읽지 않게 합니다.

    입력: 검증된 가중치 · 실행 규격
    출력: 배포 manifest · student checkpoints
    다음 단계: 배포에서 policy.py가 이 bundle을 로딩합니다.

    배포에 전달할 파일

    pick.pt / place_on.pt
    Student checkpoint와 실행에 필요한 설정만 가져갑니다. 접근 코드는 재사용하되 실기 sensor/controller backend는 별도 검증합니다.

    입력: Student export 결과
    출력: 실행용 배포 bundle
    다음 단계: Student 배포 그림의 policy.py에서 사용합니다.

실행기 하나, policy 두 개

다섯 태스크에서 같은 pick·place_on 역할을 모아 학습합니다. 태스크에 따라 객체 선택과 goal·시작 규격이 달라집니다. 객체와 목표를 policy 관측에 포함합니다.

상위 호출은 우선 코드로 유지합니다. 두 skill 외의 조리·자르기 등은 별도의 실행 흐름이 필요합니다.

모든 행동은 같은 adapter로

코드·policy·사람 입력의 단위와 action 의미를 맞춥니다. Code의 pose 목표와 policy action이 다르면 adapter에서 변환합니다.

전환 때 이전 controller 목표를 정리하고, 학습과 실행에서 동일한 command 제한을 적용합니다.

02 / 표준 시작 규격

상대 pose와 전신 자세·속도를 시작 범위로 준비합니다.

Pick

Grasp 기준점에 대한 손 pose

물체 형상·방향↓Grasp frame↓공통 pre-grasp offset

물체 중심에서 같은 거리만 띄우지 않습니다. 형상에 맞는 grasp frame을 선택하고 그 기준점에 대한 손 위치·방향과 gripper 개도를 맞춥니다.

Place_on

지지면에 대한 물체 pose

지지면·놓을 목표↓물체의 시작 pose↓실제 파지 자세로 손목 보정

Teacher의 정답 기반 설명에서는 물체↔손 transform으로 손목 목표를 계산합니다. Student 실행에서는 이 transform을 센서로 추정하고 불확실성을 고려해야 합니다. 손목만 고정하면 물체 pose가 같아진다고 가정하지 않습니다.

StartSpec에 정의할 것실행에서 확인할 것
기준 frame + 상대 pose 목표위치·방향 오차가 검증한 허용오차 안에 들어옴
손·gripper / 파지 조건Pick: 열린 빈 손 / Place_on: 올바른 물체의 안정적인 파지
로봇 자세·속도 범위Joint·torso 자세, 도달 가능성, 손끝·joint·물체 속도
Controller 전환 규칙남은 목표 정리·현재 목표 동기화·같은 명령 제한 적용
Stable window / timeout조건이 유지되면 시작 / 안 맞으면 재계획 또는 실패

정확히 한 점을 요구하기보다 좁지만 검증된 시작 범위를 씁니다. 허용오차·속도·유지 시간은 물체와 controller별 rollout으로 정합니다. 팔·torso 자세도 가능한 범위에서 맞추며, 도달 불가능한 pose를 강제하지 않습니다.

시작 조건이 통과하지 않으면?

START_BUILDER → 감속·대기

Pose가 맞아도 속도가 높으면 policy를 켜지 않습니다. 감속하고 관측한 상태를 다시 확인합니다.

03 / Skill이 지켜야 할 약속

시작·종료 조건을 policy 버전과 함께 묶습니다.

Pick SkillBundle

  • 시작: 열린 손 + pre-grasp pose + 낮은 속도
  • RL: 마지막 정렬 → 닫기 → 작은 lift
  • 종료: 올바른 객체가 안정적으로 손을 따라옴
  • 다음 코드: 실제 파지 자세에서 더 들기·이동

Place_on SkillBundle

  • 시작: 올바른 파지 + pre-place 물체 pose + 낮은 속도
  • RL: 접촉 → 해제 → 안정화·필요한 짧은 손 빼기
  • 종료: 해제 후 지지면 위에 안정적으로 남음
  • 다음 코드: 실제 종료 손 pose에서 후퇴
StartSpecObservationSchemaActionSchemaPolicy checkpointExitSpecController version

관측 정규화도 함께 고정합니다. 정해진 시간이 지났다는 이유만으로 종료 성공을 판정하지 않습니다.

execute_skill(skill="place_on", target=held_object_id,

실행기가 판정

물체가 제자리에 남았으면 새 접근을 만들 수 있습니다. 물체가 떨어졌거나 파지가 바뀌면 goal부터 다시 계산합니다. Timeout과 재계획 상한을 두고, 복구가 불가능하면 실패를 반환합니다.

학습의 episode reset과 실행 중 복구는 구분합니다. 실행 중에는 snapshot으로 물체를 원위치에 되돌렸다고 가정하지 않습니다. 무개입 평가에서는 사람 교정을 끄고 실패를 그대로 기록합니다.

Teacher는 privileged state + goal을 입력으로 받는 작은 Gaussian MLP로 시작합니다. 첫 후보는 256-unit 두 층이며 최적 크기는 validation으로 정합니다. Robot 상태·속도, 객체·지지면의 상대 상태, 파지 상태와 필요한 controller·phase 정보를 포함합니다.

원본 R1Pro action은 23차원입니다. 그 controller 의미를 기준으로 연결을 검증합니다. 국소 action을 일부 팔·gripper로 줄이면 데모 재현과 목표 도달성을 확인한 뒤 schema를 고정합니다. 46차원을 목표 feature의 필수 규격으로 가정하지 않습니다.

Replay와 state bank의 역할

Replay는 (관측, 행동, 보상, 다음 관측) 학습 데이터, state bank는 reset용 상태 cache입니다. 원본 파일을 유지하고 추출 manifest·adapter로 연결합니다.

Snapshot 복원은 속도·grasp·controller 목표까지 검증합니다. 재현이 안 되면 접근 코드를 다시 실행합니다. Code·StartSpec 변경 뒤에는 실제 handoff를 다시 평가합니다.

같은 코드로 학습과 실행

표준화 코드가 실제로 만든 시작 상태를 중심으로 학습하고 남는 오차의 유효한 근처 상태도 포함합니다. Place_on에는 학습한 pick·이동이 만든 실제 파지 자세를 넣습니다.

BC는 선택 사항입니다. BC를 했다면 같은 actor를 초기화합니다. BC 없이도 demo replay를 채우고 RLPD 업데이트로 시작할 수 있습니다.

01 / 어떤 부위를 policy가 제어하는가?

전신을 움직인다면, 전신 상태를 봐야 합니다.

Policy가 어떤 부위를 제어하는지는 action schema와 controller 설정으로 결정됩니다. 여기서는 teacher와 student가 같은 전신 action 규격을 유지하는 경우를 기본으로 설명합니다. 제어 범위를 좁히는 설계도 가능하지만, 그 경우 teacher부터 같은 제한으로 학습해야 합니다.

BASE이동·회전3 command
TORSO몸통 자세4 command
LEFT ARM왼팔 + gripper7 + 1 command
RIGHT ARM오른팔 + gripper7 + 1 command
전신 · 23차원 action

모든 제어 부위의 상태·속도를 관측합니다.

Base의 목표 대비 위치·방향과 이동 속도, torso·양팔의 joint 위치/속도, gripper와 controller 상태를 포함합니다. 접근 코드도 이를 학습에서 다룬 범위로 준비합니다.

세계 좌표의 base 위치를 매번 똑같이 맞출 필요는 없습니다. 목표와의 상대 관계와 관측 가능한 로봇 상태를 맞춥니다. 전신 움직임에 따른 카메라 시점 변화도 학습에 포함합니다.

확인한 원본 R1Pro 데이터의 action 배열은 3 + 4 + 7 + 1 + 7 + 1 = 23차원입니다. 이는 명령 배열의 차원이며 모든 물리 joint의 수나 모든 policy의 필수 출력 차원이라는 뜻은 아닙니다. 원본 61차원 proprio 배열은 별도의 관측 규격입니다. 각 command의 위치/속도 의미·단위는 실제 controller와 연결해 확인합니다.

동일한 손목 pose여도 팔꿈치와 torso는 다를 수 있습니다.

IK 해가 여러 개이기 때문입니다. Joint 자세를 기준 자세 주변의 도달 가능한 범위로 제한하고, 그 범위의 변화를 관측·학습합니다. 모든 물체에 하나의 절대 joint pose를 강제하면 도달할 수 없는 경우가 생깁니다.

Student뿐 아니라 CODE·GATE·EXIT까지 실행 경로 전체가 deployable 관측만 사용합니다. Goal은 상위 요청과 센서에서 해석한 목표입니다. 정답 물체 world pose를 goal 필드에 숨겨 넣지 않습니다.

Pick

코드가 추정한 grasp 후보 근처까지 갑니다. Student는 화면의 손·물체 관계를 보면서 마지막 정렬, gripper 닫기, 작은 lift까지 수행합니다. 성공 확인 후 코드가 이동을 이어갑니다.

Place_on

코드가 추정한 지지면 위까지 이동합니다. Student는 물체·지지면·손의 관계를 보며 마지막 정렬, 접촉, 해제, 안정화를 수행합니다. 물체가 놓였는지 센서로 확인한 뒤 후퇴합니다.

정밀 policy를 “손가락 닫기/열기”만으로 너무 짧게 자르지 않습니다. 접촉 전 마지막 정렬부터 포함해야 접근·인식 오차를 보정할 여지가 생깁니다. 카메라는 현재 제공 영상과 실기 센서 구성을 기준으로 정하며, depth·force·tactile 센서를 기본 제공으로 가정하지 않습니다.

04 / 같은 자세로 시작했는데 물체 위치가 틀리면?

추정 오차를 없애기보다, 보정할 여유를 남깁니다.

GATE → STUDENT

작은 잔여 오차는 student가 보며 보정합니다.

로봇 자세·속도가 준비됐고 대상도 잘 보입니다. 추정 중심만 믿고 바로 닫지 않고, 마지막 상대 정렬을 영상 피드백으로 조정합니다.

그림은 개념 설명용입니다. 실제 물체 위치를 실행 시 안다는 뜻이 아닙니다. 점선은 수치나 보장된 신뢰구간을 표시하지 않습니다. 시작 범위와 추정 품질 기준은 실제 rollout 검증으로 정하고, gate의 오판도 따로 측정합니다.

보이지 않는 정보는 distillation만으로 복원되지 않습니다.

같은 영상·이력인데 다른 행동이 필요한 상태가 있다면, teacher의 정확한 행동을 그대로 배울 수 없습니다. 관측 이력, 다른 카메라 시점, 재관측 동작으로 상태를 구분하도록 설계를 바꿉니다. Pose 추정기가 있어도 이런 모호함이 자동으로 해결되지는 않습니다.

05 / Teacher부터 Student 실행 조건으로 학습

추정 기반 접근에서 나온 상태를 teacher의 출발점으로 씁니다.

1

공통 실행 계약과 센서 경로 고정

Action mask·단위·좌표·제어 주기·명령 제한을 정합니다. 영상→추정→코드→gate를 시뮬레이션에서 실제로 실행합니다. 인식 모델을 정답 label로 학습하는 것은 가능하지만, 실행 추정기에 정답 상태를 넣지는 않습니다.

2

실제 handoff 상태 bank 수집

접근 코드가 끝난 전신 상태와 controller 상태를 snapshot으로 저장합니다. 카메라 보정·영상·tracking 오차, 지연, torso·팔 자세, 파지 자세를 바꿔 수집합니다. 시간에 따라 이어지는 bias와 가림도 포함합니다. 과도하거나 물리적으로 불가능한 상태를 무작정 만들지 않습니다.

Snapshot의 정답 상태는 sim reset·학습·분석용입니다. Student와 접근 코드의 관측 입력이 아닙니다.

3

Pick / Place_on State teacher 학습

이 bank와 같은 추정 기반 접근으로 teacher를 시작합니다. Teacher에는 정답 물체·지지면·파지 상태 등 privileged 정보를 줍니다. 선택적 BC 초기화 후 SAC/RLPD와 HIL 교정을 결합합니다. 짧은 자동 rollout으로 연결을 검증하고 HIL을 붙입니다.

사람의 교정도 동일 action adapter를 통과시키고 실제 실행 행동을 replay에 저장합니다. Teacher가 성공했다고 센서 기반 종료 검사도 정확하다는 뜻은 아니므로 각각 검증합니다.

4

Visual student에 distillation / BC

동일 실행 경로의 teacher rollout에서 (영상·proprio·goal·이력, teacher action)을 수집합니다. 원본 데모도 사용할 수 있지만 동일 action·영상 시점으로 연결해 검증합니다. Student도 두 개의 goal-conditioned policy로 구성하고 teacher와 같은 제어 범위를 사용합니다.

RGB encoder + proprio/goal encoder + 시간 이력 모델을 사용할 수 있습니다. ACT·DP·flow는 student 행동 모델의 후보입니다. 전신 teacher 출력을 일부 잘라 arm-only student로 만드는 것은 동일한 distillation이 아닙니다.

5

Student rollout → teacher 교정 → 재학습

Student가 직접 움직이면 teacher 데이터에 없던 오차가 생깁니다. Simulator에서 student가 방문한 상태의 정답을 teacher에게만 주고 올바른 행동 label을 추가합니다. 이 DAgger 방식의 반복으로 student의 실제 상태 분포를 학습합니다. Teacher가 복구 가능한 상태인지도 검증합니다. 근거 논문 ↗

원본 데이터와 label은 재사용합니다. 다만 원본 데이터만으로 새 추정기·코드·student가 만든 모든 상태가 포함되지는 않습니다. 추가 시뮬레이션 rollout과 검증이 필요합니다.

위 모듈 이름은 구현 제안입니다. 지정 저장소에 이 전체 framework나 HIL trainer가 이미 제공된다고 주장하는 것이 아닙니다. RB-Y1 설정을 R1Pro로 이름만 바꾸지 않고 controller·관측 배열을 검증해야 합니다.

08 / 연구 근거와 적용 범위

논문 원리를 이 설계에 적용했습니다.

Intermittent Visual Servoing · ICRA 2021거친 이동과 정밀 구간의 학습된 시각 보정을 결합. 수술 로봇 실험이며 R1Pro 성능 증거는 아닙니다. DAgger · AISTATS 2011학습된 policy가 방문하는 상태에 전문가 label을 추가해 순차 실행의 분포 차이를 줄이는 근거. Asymmetric Actor Critic · RSS 2018영상 actor와 정답 상태 critic을 구분하는 근거. Teacher→student distillation과는 별도 학습 방식입니다. Distilling Motion Planner Augmented Policies · CoRL 2021계획기를 결합한 전문가를 visual policy로 학습하는 관련 연구. 이번 접근 코드·gate의 센서 설계 자체를 제공한다는 뜻은 아닙니다. HIL-SERL · 공식 프로젝트데모와 online rollout, 사람 교정을 함께 사용하는 off-policy 학습 구조. R1Pro 실행 adapter는 별도 구현·검증. 지정 저장소 · 확인한 고정 commit기존에 확인한 2026 R1Pro 데이터·23차원 action 기준 유지. 최신 branch를 새로 확인했다는 뜻은 아닙니다.

이 페이지의 전체 통합 구조·StartSpec·gate 설계와 실험 순서는 제안입니다. 수치 기준과 성공률은 앞으로 측정해야 합니다.

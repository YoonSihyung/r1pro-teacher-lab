01 / 왜 이 순서인가?

RL을 충분히 끝낸 다음에 사람을 붙일 필요가 없습니다.

학습 효율

초기 실패에 교정이 가장 유용

Pick이 물체를 지나치거나 place_on이 지지면을 못 찾으면, 성공 보상을 거의 못 봅니다. 사람이 잠깐 올바른 행동을 실행하면 성공으로 이어지는 전이가 replay에 들어갑니다.

구현 검증

짧은 자동 RL은 먼저

행동의 방향, 보상, reset, buffer 저장과 learner 업데이트가 맞는지 확인합니다. 목적은 연결 오류를 찾는 것입니다. 정책이 수렴할 때까지 기다리는 단계가 아닙니다.

사람의 시간

반복 실패에 집중

시뮬레이션의 자동 rollout은 계속 돌리고, 반복해서 막히는 상황에 사람이 개입합니다. 정책이 회복을 익히면 제어권을 돌려주고 개입을 줄입니다.

선택의미와 판단
자동 RL 수렴 → HIL기존 정책이 이미 잘 작동하면 보완에 유용. 지금처럼 teacher를 새로 만들 때는 초기 탐색 비용을 먼저 치르게 됩니다.
짧은 자동 검증 → 초기부터 HIL이번 실험의 추천. 연결을 확인하고, 성공이 드문 초기부터 데모와 사람 교정을 같은 off-policy learner에 활용합니다.
HIL → 점차 자동 RL별도 알고리즘 전환 없이 개입만 줄입니다. 같은 actor·Q critic·replay를 계속 사용합니다.

자동 RL baseline을 비교할 때는 초기 데모·모델·환경 조건을 맞추고, 환경 step과 실제 시간에 더해 사람의 개입 시간도 보고합니다. 어느 방식이 더 빠른지는 실측으로 판단합니다.

Transition에는 무엇을 기록하나?

04 / 이번 teacher 설계

HIL-SERL의 학습 loop를 상태 기반 teacher에 적용합니다.

Teacher 입력과 모델

로봇 proprioception + 대상 객체의 상대 pose·속도·크기 + 목표 지지면·파지 상태·goal을 사용합니다. 목표 역할별 입력과 mask로 다섯 태스크를 통합합니다.

첫 후보는 2층 256-unit MLP Gaussian actor와 별도 Q critics입니다. SAC에서는 tanh와 action scaling을 포함해 controller 범위에 맞춥니다. 이 크기는 실험 출발점이며 검증된 최적값은 아닙니다.

46차원은 이 실험에 반드시 지켜야 할 규격이 아닙니다. 원본 데모의 61차원 로봇 state와 목표·객체 feature의 차원은 서로 다른 항목입니다.

보상과 BC 초기화

Pick은 대상 객체의 올바른 파지, place_on은 올바른 지지면 위에 안정적으로 놓였는지 검사합니다. Skill goal과 timeout을 정의하고 replay에서 성공·실패 사례로 검증합니다.

시뮬레이터의 신뢰할 수 있는 success predicate가 있으면 sparse reward로 사용합니다. 원 논문의 영상 reward classifier를 별도로 학습할 필요는 없습니다.

BC는 선택 사항. 같은 Gaussian actor를 원본 skill 데모로 짧게 초기화하면 무작위 탐색을 줄일 수 있지만 효과는 평가해야 합니다. BC 없이 demo buffer를 채우고 RLPD로 시작하는 것도 가능합니다.

시뮬레이터와 learner는 논리적으로 분리합니다. 같은 GPU에서 먼저 검증할 수 있고, 자원·패키지 충돌이나 처리량 때문에 별도 프로세스/환경으로 나눌 수 있습니다. GPU 두 대가 필수인 구조는 아닙니다.

이전에 설명한 PPO에서 바뀌는 부분

표준 HIL-SERL에 맞춰 teacher의 학습 알고리즘을 SAC/RLPD로 바꿉니다. PPO의 on-policy rollout과 V critic을 그대로 두고 사람 행동을 섞는 방식과는 다릅니다. Off-policy replay와 Q critics를 처음부터 준비하면 이후 사람 개입을 줄일 때도 같은 학습기를 계속 쓸 수 있습니다.

제공 데이터를 그대로 재사용

원본 파일은 유지하고 기존 label로 두 skill을 선택합니다. Episode split, 정규화, goal 연결과 (s,a,r,s′) 전이 구성은 학습용 adapter에서 처리합니다.

저장소 문서에는 영상과 state의 시점 차이가 보고되어 있습니다. Student 데이터 수집·기존 영상 재사용 시 동기화를 확인하며 모든 episode에 같은 보정을 무조건 적용하지 않습니다.

R1Pro adapter는 필요

RB-Y1과 R1Pro는 torso 관절 수, joint 이름, IK, gripper와 카메라 설정이 다릅니다. 로봇 이름만 바꾸면 동일한 행동을 실행한다고 볼 수 없습니다.

원본 R1Pro 행동은 23차원입니다. 처음에는 원본 controller 의미를 유지하고 인간 입력을 같은 공간으로 변환합니다. Gripper를 연속 명령으로 둘지 binary hybrid head로 둘지도 확인합니다.

공식 HIL-SERL은 Franka 중심의 영상 학습 코드입니다. R1Pro 환경 wrapper와 privileged-state actor 연결은 별도 구현입니다. 기존 JAX 설치 pin도 Blackwell 환경에서 검증해야 합니다.

관측·행동을 하나의 규격으로

대상을 annotation에서 찾아 “조작 객체” 슬롯에 넣습니다. 상대 좌표계, 자세 표현, 관절 순서와 정규화를 BC·RL에서 같게 유지합니다. 필요한 필드가 데모에 없으면 replay 시 추출해야 합니다.

기존 R1Pro 설정의 23차원 행동을 우선 재사용하는 제안입니다. controller 모드, absolute/delta 해석과 제어 주파수까지 일치하는지 확인합니다. [3]

SkillTeacherEnv가 연결할 것

reset(): 학습 snapshot 선택 → 복원 → 물리 안정화 → 전제조건 검사.

step(a): 행동 실행 → 새 관측 → reward → success / timeout.

Goal 검사는 환경의 완료 기준입니다. 접근 거리 같은 dense reward와 시간 비용은 별도 설계합니다. 초기 상태부터 goal이 참인 잘못된 episode도 확인합니다.

Teacher에도 모든 정보를 무조건 넣을 필요는 없습니다.

로봇·목표 물체·지지면·관련 장애물 상태부터 시작하고, 실패 원인이 숨겨진 정보에 있을 때 추가합니다. Gaussian 정책은 같은 관측에서 여러 행동 방식이 섞이면 평균 행동이 부적절할 수 있으므로, 사용하는 팔과 목표 조건을 명확히 하고 closed-loop 결과를 확인합니다.

보상으로 actor·critic 개선

pick과 place_on은 각각 독립된 actor·critic으로 학습합니다. Teacher를 ACT로 먼저 학습할 필요는 없습니다. PPO 알고리즘 코드는 재사용할 수 있지만 BC 초기화와 skill 환경 연결은 추가 구현입니다. [4]

BC가 잘 연결됐는지 먼저 확인

아주 작은 학습 subset에 action loss를 낮출 수 있는지 확인하고, teacher를 환경에 넣어 closed-loop로 실행합니다. 데모를 재생하는 것과 policy가 직접 제어하는 것은 다른 검증입니다.

평균 행동을 먼저 맞추고 PPO에서 쓸 탐색 분산을 관리합니다. Critic은 rollout 보상으로 학습하고, 필요하면 actor를 고정한 짧은 critic 준비 단계를 둡니다.

PPO에서는 실패 상태를 분석

손 접근 실패, 잘못된 물체, grasp 실패, 잘못된 지지면, release 실패를 구분합니다. Task별 sampling을 조절해 데이터가 많은 task 하나에 학습이 치우치지 않게 합니다.

정상 snapshot으로 시작한 뒤 유효한 범위의 작은 pose 변화와 이전 policy가 만든 상태로 확장하는 curriculum을 제안합니다.

대규모 학습 전, 처리량을 측정합니다.

RTX PRO 6000 Blackwell 96GB / RTX 5090 중 실제 사용할 GPU에서 20–30분 정도로 reset·rollout·업데이트를 포함한 순 transition/s와 VRAM·CPU 사용을 측정합니다. 환경 병렬 수는 1·2·4부터 비교합니다.

대략적인 실행 시간 = 총 transition ÷ 실측 순 transition/s. 이것은 수렴 시간 보장이 아닙니다. 기존 시간 계산기 보기

ACT는 student의 첫 비교 후보

Teacher와 student의 구조가 같을 필요는 없습니다. ACT는 영상과 로봇 상태에서 행동 sequence를 학습하는 후보입니다. DP도 비교할 수 있지만, 현재 단계는 teacher 학습을 먼저 검증하는 것입니다. [5]

Chunk 길이와 실제 실행할 action 수는 제어 주파수·반응성을 고려해 validation에서 선택합니다. Student의 행동과 teacher의 controller 규격은 같게 유지합니다.

Student가 실패하는 상태도 보완

Teacher rollout만 배우면 student의 오차로 방문하는 상태가 학습 데이터에 없을 수 있습니다. 시뮬레이션에서 student가 방문한 상태에 teacher를 질의해 데이터에 추가하는 DAgger 방식의 보완을 고려합니다. [6]

동일한 입력으로 구분할 수 없는 목표가 있으면 추가 관측·목표 표시가 필요합니다. Teacher의 숨겨진 객체 ID를 student에 그냥 넣는 것은 영상 기반 목표 인식을 해결하지 않습니다.

Student policy 입력과 evaluator 입력을 구분합니다.

Student 실행 시 객체 정답 pose와 simulator grasp 상태를 policy에 주지 않습니다. 평가기는 별도로 privileged 상태를 읽어 성공 여부를 검사할 수 있습니다. 이 설계에서 student의 목표 지시는 사용할 수 있는 인터페이스로 제공합니다.

지금 시작할 구현 순서

Skill 한 개의 작은 실험으로 연결을 검증합니다.

  1. 선택한 다섯 태스크 중 한 train episode에서 유효한 pick·place_on 구간 확인
  2. 시작 상태 복원과 success 판정을 먼저 검증
  3. 공통 관측·행동으로 작은 Gaussian actor의 BC → closed-loop 실행
  4. 짧은 PPO run과 처리량 측정 후 다섯 태스크로 확대
  5. 검증한 teacher를 고정한 뒤 student 데이터 수집·distillation

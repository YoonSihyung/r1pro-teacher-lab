01 / 자연스러운 전환에는 두 가지 조건

시작 상태와 실행 명령을 모두 맞춥니다.

상태의 일치

RL이 다룰 수 있는 상태인가?

물체와의 상대 위치·방향뿐 아니라 joint 위치와 속도, gripper 개도, 잡힌 물체의 자세, 접촉, controller 내부 목표가 다를 수 있습니다.

해법: 실제 코드의 종료 상태에서 학습하고, 검증으로 정한 시작 조건을 코드에서도 만족시킵니다. 상대 좌표는 불필요한 세계 좌표 차이를 줄이지만 모든 차이를 없애지는 않습니다.

제어의 연속성

전환 직후 명령이 튀지 않는가?

알고 있는 상태라도 코드의 위치 목표와 RL의 속도 명령이 서로 다른 의미라면 전환 시 움직임이 튈 수 있습니다. 이전 trajectory나 IK 목표가 남아 있어도 문제가 생깁니다.

해법: 같은 저수준 controller·단위·좌표계를 사용하고, 접근 마지막에 감속합니다. 목표 동기화와 명령 변화 제한을 학습 때부터 적용합니다.

Gaussian actor의 표준편차는 탐색의 양입니다. 그 값만으로 OOD나 성공 가능성을 판단할 수 없습니다. Q값도 검증하지 않은 상태에서는 과대평가될 수 있습니다.

03 / 논문에서 어떤 아이디어를 가져올까?

이번 문제와 가까운 논문 다섯 편입니다.

먼저 읽기 / CoRL 2024

SPIRE: Synergistic Planning, Imitation, and Reinforcement Learning for Long-Horizon Manipulation

Zihan Zhou, Animesh Garg, Dieter Fox, Caelan Garrett, Ajay Mandlekar

계획으로 풀 수 있는 구간은 TAMP, 어려운 접촉 구간은 학습 policy로 처리합니다. 계획의 precondition이 policy의 시작 상태를 정하고, postcondition이 종료 조건이 됩니다. 학습 skill 뒤에는 실제 상태에서 다시 계획합니다.

학습 때도 planner를 실행해 handoff에 도달한 worker를 RL에 넘깁니다. 데모로 BC를 학습하고 RL로 개선합니다. 가장 직접 가져올 아이디어는 이상적인 reset에서만 학습하지 않고, 실제 계획 시스템 안에서 policy를 학습한다는 것입니다.

논문 §3 · Appendix H: planner와 RL 연결 · 공식 프로젝트

상태 분포 맞추기 / CoRL 2021

Adversarial Skill Chaining for Long-Horizon Robot Manipulation via Terminal State Regularization

Youngwoon Lee et al. · PMLR 출판 2022

앞 skill의 종료 분포를 다음 skill의 시작 분포에 가깝게 만드는 학습을 제안합니다. 다음 policy가 처리할 범위를 끝없이 넓히는 대신 앞 단계의 끝나는 방식도 조정합니다.

이번 적용: 코드의 목표 pose·IK 해·정지 조건을 RL이 처리할 범위로 제한합니다. 코드는 고정되어 있으므로 논문의 adversarial policy 업데이트를 그대로 사용하는 것은 아닙니다.

접촉 직전부터 학습
자율 실행과 사람 교정 축적

  1. 접근 코드와 controller를 먼저 고정합니다.

    접근 목표, 정지 조건, goal을 정합니다. 한 skill에서 실제 접근을 반복해 RL에 넘기는 상태를 수집합니다. 코드가 바뀌면 분포도 바뀌므로 버전을 기록합니다.

  2. 상태 조건으로 제어권을 넘깁니다.

    시간이나 거리만으로 자르지 않습니다. 위치·방향·속도·gripper·도달 가능성이 조건을 만족하면 RL로 넘깁니다. 밖에 있으면 정렬·감속·재계획하고, 실패하면 전체 episode의 실패로 기록합니다.

  3. 원본 데모의 정밀 구간을 재사용합니다.

    기존 pick/place_on label로 후보를 찾고, 시작·종료 predicate로 국소 구간을 추출합니다. 기존 label이 접근과 잡기의 세밀한 경계까지 제공한다고 가정하지 않습니다. 원본은 유지하고 추출 manifest를 만듭니다.

  4. 실제 코드의 전환 상태를 학습에 포함합니다.

    데모 경계, 실제 handoff, 물리적으로 유효한 근처 상태를 섞습니다. 쉬운 상태로 시작해도 마지막에는 실제 handoff 분포를 충분히 포함합니다. Pose에 독립적인 노이즈를 넣어 접촉·파지 상태를 깨뜨리지 않습니다.

  5. HIL로 약한 전환 구간을 보완합니다.

    실제 handoff에서 실패한 상황에 사람이 국소 교정을 합니다. 같은 SAC/RLPD learner로 online·intervention 데이터를 학습합니다. 어려운 상태를 buffer에 넣는 것만으로 해결되지 않으므로 교정 후 무개입 성능도 측정합니다.

  6. RL 종료 상태에서 다음 코드를 재계획합니다.

    예정된 종료 pose와 같다고 가정하지 않습니다. 실제 파지 자세와 손 위치를 읽어 lift·이동·후퇴를 생성합니다. SPIRE의 학습 skill 후 재계획과 같은 설계 원리입니다.

  7. 전체 Code → RL → Code를 평가합니다.

    이상적인 snapshot 성공률과 실제 접근 코드에서 시작한 성공률을 분리합니다. 시작 조건을 통과하지 못한 사례까지 포함해 원래 task reset을 분모로 전체 성공률을 측정합니다.

State bank와 replay buffer는 서로 다른 용도입니다.

State bank는 시작 상태를 재사용하는 reset cache, replay는 학습용 (s,a,r,s′)입니다. Snapshot을 되돌릴 때 속도, grasp attachment, 접촉, controller 목표가 재현되는지 확인합니다. 재현할 수 없다면 접근 코드를 다시 실행해 실제 시작 상태를 만듭니다.

매번 계획하는 비용이 높으면 검증한 handoff를 cache하고 새 prefix rollout도 계속 추가합니다. 코드나 controller를 바꾸면 cache를 버전별로 구분하고 현재 코드의 handoff에서 재평가합니다.

검증한 처리 범위위 조건에서의 실제 성공률 확인. 필요하면 rollout의 성공·실패로 시작 가능성 predictor를 학습하고 별도 validation으로 문턱값 조정.

시작 predicate는 처리 가능한 범위의 근사입니다. 학습한 predictor도 모든 OOD를 검출하지는 못합니다. 첫 구현에서는 명시적인 조건과 rollout 검증을 사용하고, 학습 gate는 필요해지면 추가합니다.

시작 조건 I→국소 policy π→종료 조건 G→실제 상태에서 다음 코드

목표는 실제로 넘기는 상태 대부분을 policy의 검증된 시작 범위 I에 포함하는 것입니다. 좌표 하나를 맞추거나 Gaussian 두 개를 겹치는 것만으로는 충분하지 않습니다.

06 / 명령을 잇는 방법

같은 controller를 사용하고 전환도 학습에 포함합니다.

먼저 구현

공통 controller + 국소 policy

코드와 RL을 같은 R1Pro 저수준 controller로 연결합니다. 접근 마지막에 감속하고, 현재 자세와 controller 목표를 일치시킵니다. RL의 첫 명령에도 학습 때와 같은 속도·가속도 제한을 적용합니다.

이전 목표나 적분항을 처리할 때 물체 유지가 깨지지 않는지 확인합니다. Goal, joint 상태·속도, 물체 상태 외에 동작에 영향을 주는 이전 command·phase도 필요하면 관측으로 제공합니다.

비교할 대안

기준 동작 + residual RL

근처에서 기준 controller를 유지·느린 접근으로 두고, RL이 작은 보정을 냅니다. 보정의 활성도 β를 높여 기준 동작에서 이어지는 방법을 비교할 수 있습니다.

u_exec = u_nominal + β · δu_RL

β와 nominal 목표·이력이 변하면 필요한 정보를 관측에 넣습니다. 같은 합성과 제한을 학습 때도 실행하고 접촉 구간에서 검증합니다. [Residual RL]

합성한 예시 · 실측 명령이 아님

명령이 튀는 전환과 점진적인 전환

코드의 속도 명령에서 RL의 명령으로 갑자기 바뀌는 예입니다. 상태의 일치와 별도로 명령의 변화도 확인합니다.

부드러운 명령과 성공적인 접촉은 별개입니다.

명령을 평균하는 것만으로 파지·놓기 성공이나 안정성을 보장하지 않습니다. 방향은 올바른 회전 표현으로 다루고, gripper open/close는 별도 모드로 처리합니다. 단위·의미가 다른 명령을 더하거나 절대 pose의 Euler 각을 단순 평균하지 않습니다.

원본 23차원 데모와 local action, HIL 데이터를 어떻게 연결하나?

원본 R1Pro 데모의 action은 23차원입니다. 처음에는 원래 controller 의미를 유지하는 편이 간단합니다. 편측 팔의 Cartesian 차분이나 일부 joint로 국소 action을 제한한다면 원본 데모와의 대응을 adapter에서 검증합니다. 사용하지 않는 자유도는 코드가 유지하고, 목표를 달성할 수 없을 만큼 action을 좁히지 않습니다.

사람 입력도 같은 action 정의로 바꿉니다. Replay에는 행동 주체와 실제 command, nominal, β를 기록합니다. Residual critic이 δu를 다룬다면 total action을 그대로 δu 라벨로 쓰지 않습니다. 변환 가능하면 대응하는 보정으로 바꾸고 β=0이나 제한 때문에 변환할 수 없는 step은 별도로 처리합니다. Action 변환에 맞춰 replay와 actor/critic 정의를 먼저 확정합니다.
